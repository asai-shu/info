# ポッドキャストの学習ノート作り

持ち主（日本の大学生）が、英語の AI ポッドキャストを **Spotify で聞きながら英語の勉強をする**ためのノートを作る。
ノートは **Google ドライブにだけ保存する**（持ち主の個人用。公開しない）。文字起こしや訳は、リポジトリには絶対に保存しない（リポジトリは公開されているため）。

- 対象の番組：**Practical AI**、**Latent Space**（`collector/podcast.py` の `SHOWS`）。2026年11月5日以降に公開された回だけ
- **Spotify にない回は作らない**
- 1回分を約3,000語（約15分）ずつの「部分」に分け、**1晩に最大3部分**訳す。終わらなかった部分は次の晩に続ける（急がなくてよい、と持ち主は言っている）
- 保存先：Google ドライブの「ポッドキャスト学習」フォルダー（ID は `data/podcasts.json` の `drive.root`）→ 番組のフォルダー（`drive.practical-ai` など）→ 回ごとのフォルダー

## 手順

1. 最新のデータを取り込む
   ```sh
   git pull --rebase origin ccr-9eb32590-esny4k
   ```
2. 新しい回を探す（7日たっても文字起こしが出ない回は、ここで自動であきらめる）
   ```sh
   python3 collector/podcast.py check
   ```
3. 今晩やる作業を一覧にする
   ```sh
   python3 collector/podcast.py todo
   ```
   出てきた順に、合計3部分まで進める（`parts` が今晩訳す部分の番号）。途中の回が先に並ぶ。
4. 1回ずつ、次のことをする
   1. **文字起こしを取る**（スクラッチパッドの中の新しい空のフォルダーに保存する。リポジトリの中には置かない）
      ```sh
      python3 collector/podcast.py fetch 回のID --out （スクラッチパッド）/podcast/回のID
      ```
      - 部分ごとのファイル（`part-1.txt` …）と、全体（`full.txt`）ができる。結果の `parts` に、各部分の時間（start〜end）が出る
      - `ok: false` のとき：まだ文字起こしが出ていない。今晩は飛ばして次の回へ（7日たつと自動であきらめる）
      - `problems` に「ロボット確認で止められた」とあっても、ブログ記事から取れていれば `ok: true` になる。そのまま進めてよい
      - 文字起こしの取得元が読み取りを断っている場合に、ブラウザのふりをするなどしてすり抜けることはしない
   2. **Spotify にあるか確かめる**（`spotify_url` が空のときだけ）
      - Spotify コネクタの search で「番組名 ポッドキャストのエピソード「回のタイトル」」を探す（language は ja-JP）
      - 番組名とタイトルが一致するエピソードがあれば、URL を `https://open.spotify.com/episode/（ID）` の形にして（`?` から後ろは消す）記録する
        ```sh
        python3 collector/podcast.py update 回のID --spotify https://open.spotify.com/episode/…
        ```
      - 見つからないとき：配信が遅れているだけのこともあるので、今晩は飛ばす。公開から7日たっても見つからなければ `update 回のID --skip "Spotify で配信されていません"` であきらめる
   3. **回のフォルダーを作る**（`drive_folder_id` が空のときだけ）
      - Google ドライブのコネクタの create_file で、番組のフォルダー（`drive` の番組 ID）の中に、名前「`公開日（YYYY-MM-DD） 回のタイトル`」、contentMimeType `application/vnd.google-apps.folder` で作る
      - `python3 collector/podcast.py update 回のID --folder 作ったフォルダーのID`
   4. **まとめを作る**（`needs_summary` が true のとき＝その回の最初の晩だけ）
      - `full.txt` を全部読んでから書く。ファイル名「`00 まとめ｜回のタイトル`」。中身は下の「まとめの形」
   5. **部分ごとのノートを作る**（今晩の `parts` の番号の分だけ。`parts_total` を超えないこと）
      - `part-N.txt` を読んで書く。ファイル名「`0N 第N部（start〜end）｜回のタイトル`」（番号は2けた。end が「最後」なら「（start〜最後）」）。中身は下の「部分のノートの形」
      - 1部分作るごとに進み具合を記録する（途中で止まっても、次の晩に続きから再開できるように）
        ```sh
        python3 collector/podcast.py update 回のID --parts-done N
        ```
5. 進み具合（`data/podcasts.json`）を GitHub に送る。**このファイル以外は送らない**
   ```sh
   git add data/podcasts.json
   git commit -m "ポッドキャストの学習ノートを作成（進み具合を記録）"
   git pull --rebase origin ccr-9eb32590-esny4k
   git push origin HEAD:ccr-9eb32590-esny4k
   ```
6. 報告する（日本語で短く）：今晩作ったノート（番組・回・第何部）、あとどれだけ残っているか、飛ばした回とその理由

## Google ドキュメントの作り方

Google ドライブのコネクタの create_file で、`parentId` に回のフォルダーの ID、`contentMimeType` に `text/html`、`textContent` に HTML を渡す（自動で Google ドキュメントに変わる。見出し・太字・箇条書き・色・リンクが使える）。
作ったら read_file_content で、中身が空でないことを確かめる。

## まとめの形（00 まとめ）

```html
<html><head><meta charset="utf-8"></head><body>
<h1>まとめ｜回のタイトル</h1>
<p><b>番組：</b>番組名　<b>公開日：</b>2026年11月5日　<b>長さ：</b>約48分<br>
<b>Spotify で聞く：</b><a href="SpotifyのURL">SpotifyのURL</a><br>
<b>元のページ：</b><a href="link">link</a></p>
<h2>ひとことで言うと</h2>  … 2〜3文
<h2>要約</h2>  … 話の流れがわかるように、段落3〜5個
<h2>大事なポイント</h2>  … <ul><li> で5〜8個（誰の発言かを（ ）で添える）
<h2>出てくる人</h2>  … 名前・所属・どんな人か
<h2>知っておくと聞きやすい言葉</h2>  … 専門用語・会社名・背景知識を、やさしい日本語で
<h2>この回の構成</h2>  … 第N部（start〜end）ごとに、何の話か1行で
<h2>おすすめの聞き方</h2>  … まとめを読む → 単語の解説を見る → Spotify で英語で聞く → 全文訳で確かめる
</body></html>
```

## 部分のノートの形（第N部）

```html
<html><head><meta charset="utf-8"></head><body>
<h1>第N部（start〜end）｜回のタイトル</h1>
<p><b>番組：</b>…　<b>公開日：</b>…　<b>この部分：</b>start〜end（全M部のうちN）<br>
<b>Spotify で聞く：</b><a href="…">…</a></p>
<h2>この部分のあらすじ</h2>  … 3〜5文
<h2>全文訳</h2>
<p><span style="color:#888888">[時刻] 話し手</span><br>英語の原文（文字起こしのまま）</p>
<p><span style="color:#1f4e79">日本語訳</span></p>
… 段落ごとにくり返す …
<h2>単語・表現の解説</h2>
<p><i>（ ）内の時刻は、Spotify でその言葉が出てくるおおよその位置です。</i></p>
<h3>① AI・IT の専門用語</h3>
<h3>② 難しい単語（英検準1級〜1級レベル）</h3>
<h3>③ TOEIC によく出る単語</h3>
<h3>④ 大学受験によく出る単語</h3>
<h3>⑤ イディオム・句動詞・話し言葉の表現</h3>
（各項目の形）
<p><b>単語</b>（品詞）意味<br>
番組では：英語の文（時刻）<br>
訳：その文の訳<br>
ポイント：語源・関連語・よく出る形・まぎらわしい語との違い・発音の注意など</p>
<p style="color:#888888">次の部分（第N+1部：start〜end）は、次回の更新で追加されます。</p>
</body></html>
```

### 全文訳のルール

- **省略しない**。文字起こしの段落を全部、順番どおりに訳す（広告の部分も訳す）
- 英語の原文は、文字起こしのまま載せる（言い直し・つかえもそのまま）。訳は、言い直しやつかえを整理した、自然で読みやすい日本語にする
- 自動の文字起こしの聞き間違い（例：Norita → Narita、Grock → Grok）は、正しい意味で訳す。目立つものは「この部分のあらすじ」の下に、<i>※</i> で短く注意書きする
- 人名・会社名・製品名は原文のまま。専門用語はかっこで短く補う（例：「LLM（大規模言語モデル）」）
- 話し手の名前がない文字起こし（Latent Space など）は、「話し手」を省いて時刻だけにする。誰が話しているか文脈から明らかなら、訳のほうで補ってよい
- 原文にないことを足さない

### 単語・表現の解説のルール

- その部分に実際に出てきた語句だけを選ぶ。①〜④は各6〜9個、⑤は8〜12個が目安
- ③ TOEIC はビジネスの場面で出る語（採用・会計・契約・予算・締め切りなど）、④ 大学受験は共通テスト〜難関大の長文で出る語、② はそれより難しい語・専門的な語
- 同じ回の前の部分ですでに解説した語は、なるべく選ばない（前の部分のドキュメントを read_file_content で見て確かめてよい）
- 「ポイント」は、覚えるのに役立つことを1〜2文で（語源、派生語、よく出る形、似た語との違い、発音の注意）

## 守ること

- リポジトリでは `data/podcasts.json` 以外のファイルは変更しない。文字起こし・訳・単語の解説はリポジトリに書かない
- AI の API や外部の翻訳サービスは使わない（訳すのはあなた自身）
- Google ドライブのファイルを消したり、上書きしたりしない（作るだけ）。同じ部分を二重に作らないよう、作る前に `todo` の番号を確かめる
- 使用量の上限が近いときは、3部分より少なくてもよい。進み具合を記録して終える
